# HTML RVM — нормативный словарь

Статус: **REQ-NORM-001 candidate**. Этот документ определяет терминологию для новых атомарных Requirements; принятые S0-файлы не переписываются до отдельной авторской приёмки.

- **capability** — явно переданное доверенным host право вызвать конкретный интерфейс/эффект. Наличие данных, кода или ссылки само по себе capability не создаёт.
- **trusted host** — код приложения вне недоверенной программы МО, который владеет политикой доступа и решает, какие capabilities выдавать RVM/ChangeGateway. «Trusted» относится к authority boundary, а не к криптографической корректности документа.
- **minimal authority** — набор capabilities, необходимый только для текущей разрешённой операции; writer capability отсутствует, пока она отдельно не разрешена.
- **consistent snapshot** — зафиксированный данным provider набор версий документов, к которому относятся все read через один snapshot handle.
- **immutable snapshot** — snapshot, наблюдаемое содержимое которого не меняется после открытия; более новые commit не подменяют его значения.
- **verified snapshot** — snapshot, для которого provider успешно выполнил применимые ему проверки доступности/целостности до выдачи данных. Термин не означает обязательную криптографию для MemoryProvider.
- **working state / WorkingSession** — отделённое от snapshot изменяемое JSON-состояние одного исполнения; его мутации не являются commit.
- **PersistenceIntent** — явная сущность/намерение языка МО, предлагающая сохранить выбранный эффект; не является writer capability и не является DBMS API.
- **ChangeRequest** — storage-neutral предложение изменения, содержащее исходный base snapshot и выбранный эффект/изменения; оно ещё не является опубликованным commit.
- **current main snapshot/head** — версия, которую provider/host считает авторизованной текущей для публикации; исторически корректный snapshot не становится current только из-за валидности.
- **alias normalization** — заранее определённое отображение разрешённых alias в каноническую логическую идентичность; неизвестный alias не исправляется эвристически и не сливается с нулём/отсутствующим значением.
- **resource bound** — явный конечный лимит ресурса (например, глубины, числа шагов/узлов, размера или времени) конкретного runtime/profile. Превышение должно завершаться машинно различимой ошибкой RESOURCE_LIMIT, а не зависанием или неограниченной рекурсией.
- **atomic commit (provider scope)** — публикация всех изменений одного commit целиком или отсутствие их публикации внутри одного provider instance.
- **verified_by** — отношение к исполняемому тесту/верификатору, которое считается достаточным свидетельством всего normative утверждения Requirement в заявленном scope. Частичный пример, документация, type-check или planned scenario не получают verified_by.
- **MUST_FOR_NEXT_STAGE / SHOULD / LATER** — implementation priority: соответственно gate следующего этапа; важное, но не блокирующее следующий этап; требование более позднего roadmap. Priority не меняет lifecycle/authority Requirement.
