# MO Studio R0 — interactive integration candidate (#27)
The accepted reference executor is imported without modification. Studio owns only one active semantic state, R0 N/P tables. All native operations, atomic batches and JSON edits delegate to R0. Plain projection is derived and may reject; lossless serialization is separate. The JSON operation path is an array of typed strings/indices; editing is disabled outside the canonical tree domain. Native owner/target selection is sort-aware and relations can refer to relations. Identity inspector and used sets expose lifetime history. A session reset or import is explicit and replaces the session, not a semantic mutation. No DBMS, writer, implicit storage, arbitrary code evaluation or carrier refinement.
The existing S1A JSON Lab and DocumentPort contracts remain separate; the Pages build includes both. This candidate has not been independently accepted or deployed. Native operations form covers all R0 operation names, with JSON inputs for typed labels/payloads/roots and atomic batches. Layout is table-based rather than a graph canvas. Tests exercise state integration and packaging, not browser interaction automation.
